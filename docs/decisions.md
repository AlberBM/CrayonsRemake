# Crayons Studio Remake: design decisions

Decisions taken while building from the clean-room spec (`spec.md`, `behavior/*.md`).
"Spec" items restate decisions the spec makes (mainly spec §8.9); "Builder" items are
choices made during implementation where the spec left room. Each builder item that
carries real uncertainty also appears in `open-questions.md`.

## From the spec

| # | Decision | Source |
|---|---|---|
| S1 | Tool drawing uses real Win32 GDI on 32-bpp DIB sections (pens, `LineTo` excluding the end pixel, `R2_XORPEN`, `Ellipse`, `Polygon`). GDI+ is used only to decode BMP files. Presentation is `StretchBlt` with `COLORONCOLOR` (nearest neighbour). | spec §3.1 |
| S2 | Colours are passed to GDI as plain RGB from the 211-entry table; 256-colour palette snapping is not emulated. XOR rubber bands therefore XOR RGB values, not palette indices. | spec §3.2, §8.9 |
| S3 | One shared `DelphiRandom`, seeded from the clock when a studio starts; every documented random call is made in order, including discarded ones. `Round` is half-to-even, `Dist` uses float32. | spec §3.3 |
| S4 | Canvas mouse moves are coalesced to at most one per 20 ms (latest position kept). This approximates Win16 event density for speed-dependent tools such as Thick/Thin. A pending move is flushed before the mouse-up. | spec §3.4 |
| S5 | Formula sizes use W = 558, H = 386 (the original's outer panel size); the canvas client is 556 x 384 at (83,93) and GDI clips at its edge. | spec §4.2 |
| S6 | The UI is a fixed 640x480 frame, letterboxed; the banner is always A911A at x = 498. | spec §3.10 |
| S7 | Prev/anchor points follow tools-lines.md C4 (prev = press point, then the current point after each move; anchor set on press only). | spec §8.9 |
| S8 | Toolbar is drawn procedurally to reproduce the observed pixel map; tab left-click uses localX = x - 82, tab = 0 if localX < 45 else (localX - 10) div 40. | spec §8.1 |
| S9 | Option triangle is always red (#FF0000). Shade cells are ellipses with a #9B9B9B pen; the X marker is a rectangle plus both diagonals (#FCFC7C when colour group 9 is active, otherwise #FF0000). | spec §8.2 |
| S10 | `input.md` is canonical for hotspots (half-open rects). Thirds are 0-26 / 28-53 / 55-79; x = 27 and x = 54 play SND96 and change nothing. The shade click area is 181 <= y <= 212. | spec §8.3 |
| S11 | Panel value → bitmap mapping is the spec §8.3 table. | spec §8.3 |
| S12 | Cursors come from CRAYON2.EXE for both levels, scaled by round(frame scale) (minimum 1) with the hotspot scaled too. | spec §8.4 |
| S13 | Tooltip: SYSTEM_FONT black labels stacked from y = 0, left 2, yellow panel with a 1-px black border, height = sum of label heights + 2, width = widest + 10, at (X, Y+16), shifted to canvasW - width when X + width >= 558. | spec §8.5 |
| S14 | Voice clips and sound effects share one playback channel; a new sound cuts off the previous one. | spec §8.9 |
| S15 | Activation restore (re-activating the app restored buffer A) is **not** reproduced. | spec §8.9 |
| S16 | PC option slot 6 runs the common option-click steps (SND94, snapshot, clear panels, marker at slot 6) and nothing else. The order form / A945 text is never shown. | spec §3.6, §8.9 |
| S17 | Older tool 12 (coloring book / activities in Older) is not exposed. | spec §8.9 |
| S18 | The Younger SO (trapezoid) panel is not drawn, but it stays clickable (Younger's click handler exists). | spec §8.9, input.md §9.4 |
| S19 | Name: "Crayons Studio Remake" (window title, message boxes). | spec §8.9 |
| S20 | Thick/Thin with d > 100 uses the 16..100 width. | spec §6 |
| S21 | Sound, music and audio-help settings are not persisted; all three start on. | spec §3.7 |
| S22 | Help: CRAYONS.HLP with a WinHelp viewer (`E:\Programs\otvdm\winhlp32.exe` or `winhlp32.exe` on PATH), else XCRAYONS.PDF (install or the lab's targets folder), else an in-frame "Help is not available on this computer." box. | spec §3.9 |
| S23 | Mr. Brush's missing `snd44.asl` plays nothing (Phase 3). Dialog positions use the DFM Left/Top values listed in spec §8.9 (later phases). | spec §8.9 |

## Builder decisions (Phase 1)

| # | Decision | Why |
|---|---|---|
| B1 | **Toolbar geometry** measured from `reference/toolbar-pixelmap.txt`: tab i's left edge is x = 85 + 41i + (y - 59) div 6 and its right edge x = 130 + 41i - (y - 58) div 6 for y = 62..91. Unselected interior white; every tab has a #646464 bottom row at y = 91. The selected tab is black inside with a white column at left + 1 (y 61..88), an #A0A0A0 column at right - 1 (y 61..89), an #A0A0A0 bottom row at y = 90, and black over rows 60-61 between its top edges. Tabs are drawn right to left (left tabs overlap right ones), the selected tab last. | Matches all 15,474 non-icon cells of the observed map (`ToolbarViewTests`). |
| B2 | **Toolbar icons are clipped** to x in [82 + 41i, 123 + 41i) and y < 91. | Observed: no icon pixel ever appears at x >= 123 + 41i, and the y = 91 line stays over icon art (tab 8). Without the clip, 35 cells differed. The left bound is inferred. |
| B3 | A left click on the toolbar past the last tab does nothing (the index is not clamped to the last tab). A right click there uses the unclamped formula, as the original's right-click handler did. | "Clamped to the tab count" is ambiguous; an empty TabSet area selecting the last tab seemed wrong. |
| B4 | Clicking the already-selected tab runs the full tab click again (SND93, Mode = 0, marker removed, animation restarted). | No evidence that the original suppressed it. |
| B5 | Undo buffer A and tooltip buffer B start white (the same as the canvas). | Initial content unknown. |
| B6 | X marker diagonals: (l,t)→(r,b) and (r-1,t)→(l-1,b) with `LineTo`, where (l,t,r,b) is the 16x16 cell. | End points not documented. |
| B7 | The options row is first drawn by the first Timer1 tick (125 ms after the studio appears), and each tick blits the current frame and then advances the ping-pong (0,1,..,5,4,..,0,1,...). | First paint does not draw it (shell.md §3.1); blit/advance order not documented. |
| B8 | All blits are clipped to the source bitmap: A920 is 80 px wide although the code asks for 81, A1 is drawn 81x179, the banner at its own 140x59 size, and panels clipped to 79 px wide. Destination pixels outside the source are left as they were (black from the FormPaint fills). | Reading outside a bitmap is undefined in GDI. |
| B9 | Caterpillar's clown-mode extra `Random(16)` is made at the start of each burst, before the first pen. | Its position inside the burst is not documented. |
| B10 | The tooltip is an overlay drawn over the frame. The original's buffer B semantics are kept anyway (canvas → B on show, B → canvas and option strip redraw on hide). An empty label (from "a\|\|b") is measured as " " for its height. | Matches the documented behaviour; empty-label height inferred from auto-sized labels. |
| B11 | Band tooltips (and band D's 88/115) only apply while the corresponding panel is visible. | The tooltip map lists panels; gating by flag is inferred. |
| B12 | The middle mouse button behaves like the left button on the form and canvas (the original only special-cased the right button). Toolbar tabs react to the left button only. | input.md §2.1 / tools-lines.md stroke life cycle. |
| B13 | All five ABCD options show the thickness panel. | The table lists "(Th)" only for slot 0, but the ABCD font size is thickness-based for every font. |
| B14 | EXIT → Yes plays SND99 and closes the application after the clip's length (capped at 3 s), so the sound is not cut off. The app does not return to the age picker. | The original closed right after starting the sound; the lead chose "close app". |
| B15 | Music advances by polling MCI status every 250 ms instead of MM_MCINOTIFY. If a track cannot be opened or played, the music stops (no retry), like the original, which only advanced on a notify. | Equivalent behaviour without a notify window. |
| B16 | Clicks on the canvas's 1-px border do nothing. A stroke captures the mouse: moves outside the canvas keep drawing (clipped) until the button is released. | bsSingle border is non-client; VCL controls capture the mouse on press. |
| B17 | (Phase 1 placeholder, superseded in Phases 4-5: every option action, dialog and effect is now built, including new slate's `Random(8)` call; see B45-B70.) | - |
| B18 | The canvas cursor is recomputed only on canvas mouse moves (as the original's canvas MouseMove did); everywhere else it is the default arrow. | input.md §7. |
| B19 | Message boxes: Windows 95 look (navy caption, grey face, 3D bevels, MS Sans Serif 8), the system's own question/information icon, centred in the 640x480 frame. Enter picks the first button; Y/N pick Yes/No. | spec §3.6 gives the look but not the metrics. |
| B20 | Light-source panel middle row: the left third → 9, the right third → 8, the centre third does nothing. | "left → 9, right → 8, no centre". |
| B21 | Option entries marked "—" (no entry) leave the marker under the clicked slot after the common steps; entries marked "none" remove it. | input.md §2.4. |
| B22 | `--level=younger|older` command-line switch skips the splash and age picker (developer/test convenience). | Smoke testing. |
| B23 | The left-click state machine lives in `Crayons.Core.Studio.StudioInput` behind an `IStudioEffects` interface so it can be unit-tested; `StudioScreen` supplies the GDI/audio side effects. | Testability. |

## Builder decisions (Phases 2 and 3: Paint, Wacky, Shapes, 3D)

| # | Decision | Why |
|---|---|---|
| B24 | The dispatcher still makes the clown `Random(159)` call on every move event when the colour-mode flag is on, for every mode (paint, shapes and 3D included), although only the Lines/Wacky tools use the result. Paint tools always use the current colour / tri-colour. | tools-wacky.md: `FUN_1008_1890` draws it first on every move event; the flag survives panel clears. |

| B31 | "Toward X" is applied to every Shapes midpoint formula (triangles, trapezoids, diamond, hexagon, octagon, star): offsets use the signed X-X0 / Y-Y0 (`div` truncating toward zero, `Round` half-even, which is symmetric). | B34 | The "both X and Y changed" release rule (no render, no sound) applies to all shape routines of both tabs: 0x1F..0x25, 0x28, 0x29, 0x2B..0x2E, 0x37 and the cube 0x3C. The 3D line needs either. | tools-shapes.md mouse protocol. |
| B35 | Jumble: each swap draws x1, y1, x2, y2 as `X + Random(2r) - r` / `Y + Random(2r) - r`; a swap touching an off-canvas pixel is skipped (its random calls are still made). | "two random points within ±r"; order and range inferred. |
| B36 | Smear: rows Y-r..Y+r, one `Random(4r)` per row, destination x = X - r + Random(4r) - 2r, source x = X - 2r, width 2r; nothing (and no random call) when X - 2r <= 0. | tools-shapes.md wording. |

| B38 | Mr. Brush draws its trail (width = thickness, colour captured at the click) from the new tip to the previous tip each frame; the drift flip takes the opposite sign of the current drift. Phase 1 plays SND75 and phase 5 SND74; SND76 at the end; the missing `snd44.asl` plays nothing. | tools-wacky.md, spec §3.5. |
| B39 | Train vertical drift uses the documented mapping 1→1, 2→0, 3→1 (never upward). | As documented; see open questions. |
| B40 | Barn Zoom and Shear (Younger Wacky 8/9) also serve Older Change It slots 3/4 ("Reduce", "Move Around"), sharing one implementation; they read buffer A, which the option click has just refreshed. ## Builder decisions (Phase 6: runtime corrections, spec §9.1 R1-R17)

| # | Decision | Why |
|---|---|---|
| B71 | R1 root cause: right after `play`, MCI reports `status mode` = "seeking" for about 100 ms. `IsSongPlaying` treated anything but "playing" as the end, and the first poll after a track change landed inside that window, so every 250-ms poll closed the song and opened the next one. The cascade ran PC2 to PC20 and wrapped, and each cycle blocked the UI thread for about 1.6 s (`open` ~1.0 s, `play` ~0.35 s, `stop`+`close` ~0.14 s), which gave about 1 tick per 1.6 s from the end of PC1 (63.5 s + startup, about 65 s). Fix: all MCI commands run on one background worker (`MciMusicPlayer`). The UI side only records the wanted song and reads a flag, so it never blocks. A song ends only on "stopped" or an MCI error. A song MCI cannot open or play ends the chain, as a failed start did before. Worker exceptions are caught, so music can never take the app down. | Measured: before, 1 tick per ~1.6 s from 65 s onwards; after, 58-65 ticks/s, worst gap 45 ms and 8.08 options-row frames/s across two track changes in a 163-s run. |
| B72 | R2 paint-can preview: styles 0-7 are one `Polygon` with the style brush and a 1-px pen in the current colour (hatches TRANSPARENT; style 0 null brush, so the outline only). Styles 8-15 (patterns) fill the polygon's region opaquely with **no** outline. The brush origin is the form's (0,0), not the swatch origin. Gradients use the polygon's bounding box (15,299)-(65,325); pictures still tile from (15,299). All styles 0-24 and 28 were compared pixel for pixel against `runtime/fill/d_fsp_*`, `d_grd_*` and `d_pic_*`: 0 differences. | §9.1 R2 says "outline" for every style, but the observed pattern styles have none. Observation wins. The gradient box mismatch was found in the same comparison. |
| B73 | R3: band D (captions 88 "Color Crazy" left half, 115 "Normal Color" right half) is no longer gated by the colour-mode panel, on both levels. | §9.1 R3. The spec says "Color Crazy, caption 115", but in A938/A939 "Color Crazy" is line 88. Both halves were ungated; only the left half was observed. |
